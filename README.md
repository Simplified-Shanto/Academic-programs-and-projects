# Academic Programs and Projects

This repository is a collection of coursework, laboratory exercises, practice
programs, algorithms, data structures, and small projects developed while
studying computer science. It is organized by subject so that a student can
open one course folder, study the related examples, and run the programs
individually.

The repository is educational rather than a single application. Some files are
small demonstrations, some are unfinished practice work, and some intentionally
show an error, a race condition, or a particular language feature. Read the
nearby comments and notes before treating an example as production code.

## Where to start

### Java

The Java material is the most actively organized part of the repository.

- [Java practice overview](./Java_Practise_codes/README.md)
- [Multithreading demos](./Java_Practise_codes/C11multithreading)
- [Multithreading exercise sheet](./Java_Practise_codes/C11multithreading/PYQ_Exercises.md)
- [PYQ question-bank reference](./Java_Practise_codes/reference/Java_PYQ_Bank.pdf)
- [PYQ reference notes](./Java_Practise_codes/reference/README.md)

The multithreading examples are grouped by topic:

- `A_ThreadCreationAndManagement/` contains current-thread inspection, the
  `Runnable` approach, extending `Thread`, multiple threads, `join()`, race
  conditions, synchronized methods, synchronized blocks, and protecting a
  third-party class with a wrapper.
- `B_InterThreadCommunication/` contains basic inter-thread communication.
- `Practise_PYQ_codes/` contains question files. Q1 and Q2 include completed
  solutions; Q3–Q8 are comment-only templates ready for practice.
- `Exceptions/`, `CustomException/`, `JavaLabCodes/`, `lab_codes/`,
  `nested_package/`, and `package_demonstration/` cover exceptions, packages,
  laboratory problems, and Java package structure.

### Data structures

Open [`DataStructureCourse`](./DataStructureCourse) for C implementations and
read the folder names as a study sequence: graph representations and traversal,
linked lists, queues, stacks, and trees. The graph folder also contains a short
adjacency-list explanation and a diagram.

### Algorithms

[`Algorithm_Course`](./Algorithm_Course) contains focused exercises such as
graph coloring, minimum coin exchange, travelling-salesman/greedy work, and
algorithm notes. The source files use C++, Python, and related course material.

### Structured programming

[`StructuredProgrammingCourse`](./StructuredProgrammingCourse) is the C-focused
course area. It includes pointer and array exercises, sorting and searching,
structures and unions, linked-list implementations, file handling, multi-file
interaction, and student-management-system practice. Several exercises include
sample input and output files beside the source.

### Other experiments

[`Other Codes`](<./Other%20Codes>) contains smaller experiments that do not
belong to one course folder: C and C++ snippets, Python plotting scripts, HTML
pages, and a Jupyter notebook.

## Running the programs

There is no single build system. Compile the source file or small group of files
that you are studying.

### C

```bash
gcc path/to/program.c -o /tmp/program
/tmp/program
```

### C++

```bash
g++ path/to/program.cpp -o /tmp/program
/tmp/program
```

### Java

Use a JDK, and compile into a temporary output directory so generated bytecode
does not clutter the source folders:

```bash
mkdir -p /tmp/java-build
javac -d /tmp/java-build path/to/Example.java
java -cp /tmp/java-build Example
```

For the package demonstration, see the commands in
[Java_Practise_codes/README.md](./Java_Practise_codes/README.md). Java files in
the multithreading area are intentionally small demonstrations and are usually
run one file or one topic group at a time.

### Python and notebooks

Use Python 3 for the scripts in `Other Codes/[08] Python codes`. Open the
notebook in Jupyter or another compatible notebook environment.

### HTML

Open the files in `Other Codes/[07] HTML` in a browser. Some pages are simple
standalone experiments rather than complete web applications.

## Study and review workflow

1. Start with the folder for your course or current topic.
2. Read the source comments and any nearby `README.md`, notes, or sample input.
3. Compile and run one example at a time.
4. Change one part of the program and observe the result.
5. For Java multithreading, use the PYQ exercise sheet and the stored question
   bank to turn each concept into a short exam-style answer.

## Generated files and contributions

Compiled Java `.class` files are generated artifacts and are ignored by the
repository's `.gitignore`. Before committing Java work, remove any generated
bytecode across the practice tree:

```bash
find Java_Practise_codes -type f -name '*.class' -delete
```

Keep source files, explanations, and useful sample input/output files. Place
new work in the subject folder it belongs to and use a descriptive filename.
When adding a larger topic, include a short README or comments explaining what
the student should learn from it.

## Notes for readers

- Folder names and file names reflect the history of the coursework, so some
  names are intentionally course-specific.
- Program output involving threads can vary because the operating-system
  scheduler controls execution order. The synchronized examples explain which
  results are guaranteed.
- The Java PYQ bank is kept under `Java_Practise_codes/reference/` for local
  study and is mapped to the multithreading exercises there.
